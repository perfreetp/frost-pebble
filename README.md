# 街区立管与表箱布点系统

燃气公司报装班组的排布与工单系统。React + TypeScript + WebGPU，四个界面覆盖「接单建图 → 排布施工 → 质检抽查 → 施工看板」。

```bash
npm install
npm run dev      # 开发调试 (http://127.0.0.1:5173)
npm test         # 领域逻辑单元测试（49 项）
npm run build    # 生产构建
npm run preview  # 预览构建产物
```

> 需要 Chrome / Edge 113+ 才能看到 WebGPU 三维排布。不支持时视图会明确提示，而排布计算、校验与全部工单流程仍可用。

---

## 一、核心能力

### 1. 确定性排布生成

`src/domain/layout.ts` 中的 `generateLayout(params, overrides)` 是纯函数：**同一种子 + 同一组参数必然产出同一份排布**，以 12 位十六进制「排布指纹」标识（`fingerprint`），可打印、可归档、可核对。

输入参数：

| 参数 | 说明 |
| --- | --- |
| 种子 `seed` | 决定区段宽度、支管偏移与余数分组建序等全部随机自由度 |
| 楼栋数 / 每栋层数 / 每层户数 | 户数与楼层规模 |
| 管径 `pipeDiameter` | DN25 ~ DN100，决定立管与干管的实体半径 |
| 表箱规格 `boxSpecId` | BX-1(1 户) / BX-2(2 户) / BX-3(2 户加宽) |
| 街区进深 `streetDepth` | 楼栋进深，俯视图直接体现 |
| 层高 `floorHeight` | 分段名义段长 |
| 退距规则 | 退道路红线、楼栋净距、立管距墙、表箱底标高、同层箱净距 |

生成规则：

- 每栋按「每层户数」拆成立管组，单管辖 2~4 户（种子会让 4 户以上多配一根管）。
- 表箱按**户均 1~2 户**分配：单箱服务户数由表箱规格容量与该组余数共同决定，永远落在 1~2 之间。
- 立管沿街立面横向排布，表箱逐层挂在立管旁侧，层高决定竖向节距。
- 沿街低压干管自动连接各立管底部，管材总长计入统计。
- 退距规则参与校验：立管越过红线、箱底标高＋箱高超过层高、管径偏小、立管总高与楼高不符、手工表箱越界或重叠等，都产出带级别（error / warn / info）的校验项。

### 2. 手工标记与增量重算

师傅在视图里可直接拖动：

- **拖动表箱**：立面视图改横向位置与标高，俯视视图改进深（地面平面拾取，高度保持）。
- **拖动立管段**：向上拖加长、向下拖缩短，鼠标当前高度实时换算为该段长度。

被改动的对象写入工单的 `overrides`（`boxes: id → 世界坐标`、`segments: id → 段长`），并在三维视图里打上橙色手工标记旗。

**调参重生成时**：`overrides` 作为入参传入 `generateLayout`，手工对象位置按原坐标保留（`pinned: true`），其余部分全部按新参数重算。若参数变化导致已标记对象不复存在（例如层数减少），会进入 `orphans` 列表提示「手工标记失效」。立管段被加长后，其上各段整体上移，保持立管连续。

### 3. 工单状态机

```
待派 pending ──► 施工中 working ──► 待质检 qc ──┬─► 已通过 passed
                    ▲                          └─► 退回整改 rework ──► 施工中 / 待质检
```

`src/domain/workflow.ts` 的 `TRANSITIONS` 是唯一权威定义，越级流转一律被拒绝（`canTransition`）。**每次变更都通过 `makeAudit` 写入操作人、角色、时间与说明**，可在工单内「操作记录」中按时间倒序查看。

### 4. 质检 20% 抽查

按提交批次序号等距抽取：`seq % 5 === 0` 必检，长期比例恒为 20%，不依赖随机数，因此可审计、可复现。未抽中订单自动通过并写入「免抽检通过」记录；返工单 100% 复检。不合格需勾选整改项（8 条标准整改清单）退回，返工次数累计到工单并在各处展示。

### 5. 施工看板

- 指标卡：工单总数、进行中、已通过、超期单、返工率、质检抽查比例。
- 按人统计：在手、完工量（条形对比）、返工单数、返工率、超期单、平均工期。
- 近 6 个月完工趋势（含返工占比堆叠柱）。
- 工单明细表（可按状态筛选、按交期或超期排序）与超期预警列表。
- 逾期语义：未完单按当前时间比交期，已完单按完工时间比交期（不会随时间漂移）。

## 二、四个界面

| # | 界面 | 面向 | 要点 |
| --- | --- | --- | --- |
| 01 | **接单建图** | 前台派单员 | 录入小区 / 地址 / 联系人、楼栋层户、管径表箱、进深层高退距、种子；右侧实时 WebGPU 预览 + 排布指纹；可直接派单或进待派池；已派工单可一键打开工作台 |
| 02 | **排布施工台** | 施工班组长 | 我的工单列表、工单信息条、质检退回整改项；画布支持立面 / 俯视切换、拖动表箱与立管段、Shift 平移、滚轮缩放；右侧参数调整、选中对象属性、校验与手工标记汇总；完工提交（现场拍照 / 上传 + 施工说明） |
| 03 | **质检抽查** | 质量检验员 | 待质检队列（含批次与返工标识）、只读排布复核、报装参数与校验、现场照片、提交记录；合格通过 / 不合格退回（勾选整改项 + 补充说明） |
| 04 | **施工看板** | 全员 | 指标卡、按人统计、月度趋势、工单明细、超期预警，点击可跳回排布工作台 |

顶部可切换「当前身份」（前台 / 三名班组长 / 质检员），不同身份可见与可操作的内容不同（施工/质检期间排布只读，仅当班师傅可编辑）。

## 三、渲染实现（WebGPU）

- `src/gpu/renderer.ts`：原生 WebGPU 管线。两组着色器——全屏渐变天空背景 + 场景实体（半球环境光、主光、高光、距离雾）。顶点格式为位置 / 法线 / 颜色三路 interleaved，深度用 `depth24plus`。
- `src/gpu/scene.ts`：把 `LayoutModel` 编译成三角面（楼栋体量、窗格、层线、立管圆柱、分段接口环、表箱与箱门面板、手工旗标、干管、人行道 / 车行道 / 路缘石 / 红线虚线 / 网格）。同时产出 AABB 拾取表，供射线拾取使用。
- `src/gpu/math.ts`：列主序矩阵、透视 / 正交投影、屏幕↔世界射线、精确视锥求解（二分收敛，保证取景不裁切）。
- 立面用正投影（+x 向右、y 向上），并绘制层高标高尺、总长与分栋尺寸线；俯视为斜向航拍，地面扩展填满画面。
- 标注层由 Canvas2D 叠加绘制（标签带引线与高亮边框），不参与 WebGPU 绘制。

交互拾取与拖动全部走 CPU 射线求交，不依赖 GPU 回读，因此在无 WebGPU 环境下也不影响编辑逻辑。

## 四、数据与持久化

- 演示数据由 `src/data/seed.ts` 生成：10 个工单覆盖待派 / 施工 / 待检 / 已通过 / 退回整改，其中含手工标记、返工记录、抽查历史、操作日志与现场照片（内置 SVG 示意照片）。
- 状态保存在浏览器 `localStorage`（键 `gas-street-riser.v1`）。大体积照片在存储时仅保留元数据，界面内仍完整显示；「重置数据」可恢复演示样例。
- 时间基准取 `Date.now()`；种子数据的时间点固定在 2026-11-14，保证每次加载的样例一致。

## 五、测试

`npm test` 共 49 项，覆盖：

- **确定性**：同种子 / 同参数 / 规范化后的等价参数 → 指纹一致；换种子或换参数 → 指纹变化。
- **业务约束**：各层表箱服务户数合计等于每层户数；单箱 1~2 户；生成态表箱不重叠；立管总高等于各段之和；立管表箱在立面范围内；楼栋退距不重叠；总户数核算；脏输入被规范化不崩；规则冲突产出 error。
- **手工改动**：拖动表箱只影响该箱；改段长后其上各段整体上移；调参重算后手工位置保留、其余重算；层数减少时标记进入 orphans；改规格后箱体尺寸更新而位置保留；重叠产出 error；段长被限制在合理区间。
- **状态机与抽查**：合法/非法流转；20% 抽查比例与固定序号；交期随规模变化；逾期语义（未完 / 已完）。
- **看板统计**：状态计数自洽、按人分派自洽、返工率区间、月度序列、表箱总数与排布一致、空数据不崩。
- **操作日志与手工标记操作**。

无头 Chrome + Playwright 的端到端脚本在 `scripts/` 下（`create` 建单与指纹复现、`drag2` 拖动与刷新持久化、`drag3` 立管段与俯视表箱拖动、`qc` 退回与看板、`sample4` 抽检判定）。它们需要先 `npm run preview` 起服务，仅用于开发验证，不参与构建。
