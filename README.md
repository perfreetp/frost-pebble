# 桥检 · 三维病害标注与定级工作台

把“在无人机照片上圈裂缝、回办公室对着图纸猜位置”换成**直接在桥梁三维模型上标注**：
点裂缝两个端点，系统沿真实构件表面采样展开算长度与走向；宽度超 0.2 mm 标黄、超 0.3 mm 标红且必须补齐特写照片与判定依据才允许保存；
支座脱空 / 铰缝渗水用半透明体块套出；沿任意轴剖切看箱梁内部并实时显示截面标高与构件名；
同一桩号的历史病害自动串成时间线给出发展速率与提前预警；最后出分布图、统计、维修建议清单，工程师逐条确认后导出带二维码的 PDF 与只读分享链接。

## 快速开始

```bash
npm install
npm run seed      # 生成演示数据（3 年历史巡检 + 本次 8 处病害 + 演示照片）
npm run dev       # 后端 :8787 + 前端 :5173
```

打开 http://localhost:5173 。生产模式：`npm run build && npm start`（前端由后端在 :8787 一并托管）。

```bash
npm test          # 48 个单元测试（几何展开、定级、时间线、报告、multipart、UTF-8 PDF）
npm run typecheck
```

运行时依赖只有 three / three-mesh-bvh / react / zustand / pdf-lib / qrcode / express；
演示照片由内置的最小 PNG 编码器合成，中文字体从系统 TTF（Deng/simhei）嵌入 PDF，无需外网。

## 六个界面

| 界面 | 做什么 |
| --- | --- |
| **模型导入** | 点云 LAS/LAZ、倾斜摄影 OBJ/PLY/GLB、3D Tiles 的导入与解析进度；录入跨径组合，按跨径切出梁体 / 桥面铺装 / 护栏 / 墩柱 / 支座 / 桥台，并为每件挂档案编号与里程桩号 |
| **构件树** | 按构件类型分组的树，显示每件桩号区间、本批次病害数；可逐件显隐、搜索、双击聚焦 |
| **标注台** | 两个端点画裂缝（实时给展开长度 / 走向 / 桩号 / 偏距 / 标高），拖拽两点框体块（脱空、渗水）；右侧标注台即时定级并执行保存门槛 |
| **剖切查看** | 纵剖 / 横剖 / 水平剖，滑杆或自动巡览；剖切面旁标签与右上读数实时给出该截面标高、桩号与相交构件 |
| **时间线** | 同构件、桩号 ±0.35 m、偏距 ±0.5 m 内的历史病害自动归并成“病害发展线”，显示宽度/深度/影响长度的年增长速率、新增/扩展分色、接近限值的预测与提前提醒 |
| **报告** | 立面 + 平面展开的病害分布图、按等级/类型/构件的统计、维修建议清单（按“立即/汛前/下次定检/观察”排序合并），工程师逐条确认后导出带二维码 PDF，并给出只读分享链接 |

## 关键实现

### 贴合曲面展开（`src/core/surface.ts`、`src/core/annotation.ts`）
1. 拾取时用 `three-mesh-bvh` 的 `closestPointToPoint` 把屏幕点吸附到构件表面，得到表面点 + 面法向。
2. `traceOnSurface` 在两端点之间的弦上迭代取中点、吸附回曲面，直到折线贴合（同时按 0.5 m 强制打断，保证跨箱梁腹板转折时不漏采样）。
3. `unfoldPolyline` 用**平行输运**把每一段切向按相邻法向的二面角送到当前切平面，再累加测地曲率转角，得到保持弧长的展开折线 —— 长度是展开后长度，不是直线弦长（见 `tests/annotation.test.ts` 的“底板→腹板折面”用例）。
4. 走向取端点弦向在水平面内相对里程方向的夹角（左正右负），按 ≤20° 纵向 / ≥70° 横向 / 其余斜向分类。

### 定级与保存门槛（`src/core/annotation.ts`）
- 裂缝：`>0.3 mm` 严重（4 级，贯通或梁体长裂缝加到 5 级），`>0.2 mm` 需关注（2 级）；边界值归入较低一档（0.30 仍为需关注）。
- 支座脱空：脱空率 >30% 或深度 >5 mm 严重；>15% / >2 mm 需关注。
- 铰缝渗水：影响长度 >1.5 m 或面积 >1.5 m² 严重；>0.5 m 需关注。
- **严重级必须同时具备判定依据 + 至少一张特写照片**，前端按钮禁用，后端 `POST /api/defects` 再校验一次（422 + 错误码），旧数据无法绕过。
- 未确认的病害不允许导出正式 PDF（服务端 409 并列出待确认清单）。

### 剖切（`src/three/viewer.ts`）
- 材质 `clippingPlanes` 剖开，双面渲染露出内壁；再用“薄层背面”作切口实心面，叠加由真实交线生成的切口轮廓。
- 交线计算为每个构件建立**区间桶索引**（三角形放入其 [min,max] 覆盖的桶），剖切只扫相邻 3 个桶并去重。26 万面片下实测 3.6 ms/次，结果与暴力扫全量三角形完全一致（7908 = 7908）。
- 拖动滑杆时用 `requestAnimationFrame` 合帧，避免每帧重复扫描。

### 性能与文字清晰度
- 每构件独立 BVH：拾取只测命中构件，26 万面片 3.3 ms、100 万面片 10 ms。
- 标注线用 `Line2`（屏幕像素宽度），标签是 DOM 绝对定位而非 WebGL 纹理，任何缩放下中文都不糊；标签做碰撞避让，重叠时降级为同色小圆点并保留 title。
- 顶栏可切换网格密度（轻量 / 中等 / 26 万 / 100 万面片）实测帧率，视口左上角实时显示面片数与 fps。

## 目录

```
src/core/        纯 TS 领域层（无 three 依赖），前端/服务端/测试共用
  bridgeModel.ts 参数化桥梁与构件（编号、桩号、标高、包围盒）
  surface.ts     曲面吸附、折线贴合、平行输运展开
  annotation.ts  裂缝/体块测量、桩号偏距标高、定级规则、保存门槛
  timeline.ts    病害线归并、发展速率、限值预测
  reports.ts     统计、维修建议库、分布图数据
src/three/       渲染、BVH 拾取、剖切与标签投影
src/ui/          六个界面的 React 组件与两个 zustand store
server/          Express API、JSON 持久化、multipart 照片、PDF 与分享快照
tests/           48 个用例
```

数据落在 `data/`（`db.json`、`uploads/`、`shares/`、`reports/`），已在 `.gitignore` 中排除。
