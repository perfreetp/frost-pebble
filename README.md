# 引航站 · 泊位与引航调度训练系统

面向引航站学徒的泊位与引航调度模拟训练。React 19 + PixiJS 8 + Vite，纯前端运行，数据存在浏览器 localStorage。

## 启动

```bash
npm install
npm run dev        # http://127.0.0.1:5173
```

其他命令：

```bash
npm run build      # 类型检查 + 生产构建
npm test           # 单元测试（调度引擎 / 关卡数据）
npm run test:e2e   # Playwright 端到端测试（需要 msedge）
```

## 训练机制

画布是港口时间轴：左侧是锚地排队等进港的船（吃水、长度、潮窗），右侧每行一座泊位，下方是当日潮高曲线。

学员把船拖到泊位、或点选后在右侧面板排程，指派引航员和拖轮。以下动作会**当场拦截**并说明原因：

| 规则 | 说明 |
| --- | --- |
| 吃水超泊位限制 | 给出超出数值，提示会触底 |
| 船长超泊位 | 对比可容纳船长 |
| 错过潮窗 | 开始早于潮窗开启，或作业结束晚于潮窗关闭 |
| 引航员时间重叠 | 含 15 分钟离船/登船转场 |
| 泊位时段重叠 | 含 10 分钟清泊时间 |
| 早于预计到港 | 不能提前靠泊 |
| 超出训练时限 | 作业不能跨过推演结束 |
| 重复排船 | 同一条船只排一次 |

点「开始推演」后时间推进，未拦截但会演变成事故的情况逐条记为事故：

- 未指派引航员 → 无法进港，滞留锚地
- 拖轮数量不足 → 每缺一艘延迟 35 分钟
- 拖轮被其他船占用 → 连锁延误
- 引航员 / 泊位被上游延误拖住 → 连锁延误
- 延误导致错过潮窗 → 误船

## 评分

- **客观分（系统自动）**：准点率 × 50 + 无冲突分（30 − 事故数 × 8）+ 效率分（平均等待越短越高）= 100
- **最终分**：客观分 − 教员复核扣分（最低 0）

## 关卡

初级 4 关（2 → 5 条船）：双船进港、三条船与潮窗、浅水泊位的取舍、五船与引航员周转。
高级 4 关（5 → 8 条船）：潮窗收口、六船与拖轮争用、七船压港、八船满负荷。

全部内置关卡的参考计划由 `src/game/planner.ts` 的排程器生成，并有关卡测试保证满足全部硬规则、推演零事故。

## 教师端

- **复核队列**：回放任意提交（时间轴 + 逐船结果 + 事故 + 拦截记录），扣分并写评语
- **班级成绩**：按班级汇总客观分、准点率、平均等待、复核后最终分
- **错题本**：把学员被拦截的动作按冲突类型归类统计，附真实例子与班级分布
- **出题**：自设船舶清单、泊位数、引航员/拖轮、潮汐表与训练时限，保存后立即可被学员端选择；编辑器内置可行性检查与时间轴预览

## 代码结构

```
src/
  game/          领域模型、规则校验、推演引擎、排班器、潮汐计算
  data/          8 个内置关卡 + 参考计划生成
  pixi/          PixiJS 时间轴视图（拖拽、预览、播放头、事故标记）
  components/    画布挂载、通用 UI
  student/       训练台、排程页、结果页
  teacher/       复核 / 班级 / 错题本 / 出题
  storage/       localStorage 持久化与汇总统计
tests/           引擎与关卡单元测试（Vitest）
e2e/             学员与教师端流程测试（Playwright）
```

规则参数集中在 `src/game/constants.ts`：泊位周转 10 分钟、引航员转场 15 分钟、拖轮周转 10 分钟、缺拖轮延误 35 分钟/艘。
